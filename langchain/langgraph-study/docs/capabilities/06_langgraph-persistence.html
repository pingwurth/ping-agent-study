持久化

LangGraph 的持久化层通过检查点保存器为智能体提供短期记忆，通过存储为智能体提供长期记忆。

持久化使 LangGraph 应用能够在单次图运行之外保留信息。当智能体需要继续对话、从中断中恢复、从故障中恢复或跨交互记住信息时，这非常重要。

LangGraph 提供两个互补的持久化系统：

  • 检查点保存器（Checkpointers） — 将线程的图状态持久化为检查点。它们处理短期的、线程范围内的记忆，包括对话连续性、人机交互工作流、时间旅行和容错。
  • 存储（Stores） — 将应用定义的数据持久化到图状态之外。它们处理长期的、跨线程的记忆，包括用户偏好、事实和共享知识。

大多数应用同时使用两者：一个检查点保存器用于当前线程，一个存储用于跨线程的持久信息。

快速开始

使用检查点保存器、存储或两者来编译你的图：

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.store.memory import InMemoryStore

checkpointer = InMemorySaver()
store = InMemoryStore()

graph = builder.compile(checkpointer=checkpointer, store=store)

result = graph.invoke(
    {"messages": [{"role": "user", "content": "Hi, my name is Bob."}]},
    {"configurable": {"thread_id": "thread-1"}},
)

信息：Agent Server 自动处理持久化
使用 Agent Server 时，你不需要手动实现或配置检查点保存器或存储。

检查点保存器与存储的对比

检查点保存器（Checkpointer） 存储（Store）
持久化内容 图状态快照 应用定义的键值数据
作用范围 单个线程 跨线程
记忆类型 短期、线程范围内的记忆 长期、跨线程的记忆
适用场景 对话连续性、人机交互、时间旅行和容错 用户偏好、事实和共享知识
访问模式 在图配置中传递 thread_id 从节点或应用代码中读写数据项
完整指南 检查点保存器 存储

常见问题排查

PostgresSaver：thread_id 过长

使用 PostgresSaver（或 AsyncPostgresSaver）时，thread_id 存储在长度有限的列中。超出列大小会导致数据库错误。

修复方法：将 thread_id 值保持在 255 个字符以内。使用 UUID 或哈希来生成确定性 ID：

import uuid

config = {"configurable": {"thread_id": str(uuid.uuid4())[:255]}}

MemorySaver 不会在重启之间持久化

MemorySaver 和 InMemorySaver 将检查点存储在 RAM 中。进程重启后所有检查点都会丢失。

修复方法：在生产环境中使用持久化检查点保存器：

  • PostgresSaver：支持异步的 PostgreSQL
  • SqliteSaver：用于开发的本地文件存储

检查点无限增长

在长时间对话中，检查点会不断累积，增加延迟和存储成本。

修复方法：定期清理旧检查点或设置保留策略：

from langgraph.checkpoint.postgres import PostgresSaver

checkpointer = PostgresSaver.from_conn_string("postgresql://...")
checkpointer.setup()  # 创建带索引的表
# 考虑添加定时任务来删除超过 N 天的检查点

从父图到子图的状态访问

当子图更新状态时，父图可能不会立即看到更改，因为每个子图管理自己的检查点命名空间。

修复方法：使用通过 Store 共享状态来实现跨图边界的数据传递，或配置子图写入父图检查点。
